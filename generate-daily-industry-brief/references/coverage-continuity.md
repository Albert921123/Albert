# 不留空白的连续覆盖规则

目标是让每一个已选板块都有一张真实、可点击的信息卡，但不得为了填满页面虚构“今日新闻”。按以下优先级补足。

1. **实时正式资讯**：运行前 24 小时的 A/B 级可核验事件。
2. **48 小时补充**：仅当该板块没有实时正式资讯时，使用前 24–48 小时内的可核验事件，并显著标记。
3. **48小时窗口观察**：仅限权威一手来源或合格 T2 来源。若页面只写日期、没有时分，且该日期可确定落在整体滚动 48 小时范围内，先补查附件、元数据、原始记录和事件时间；仍无时分时可保留为真实资讯卡，但必须标记 `48小时窗口观察 · 原始页面未披露时分`。它不是 24 小时资讯，也不是 `48小时补充`，不得计入完成覆盖或成功标记。
4. **扩展相关资讯**：仍无 A/B 级事件时，可使用一条具有明确影响链、且时间可精确核验在同一滚动48小时内的 C 级行业、区域、监管、产业链或业务相关事件；卡片必须标记 `扩展相关资讯`，写明关联路径，且一板块最多一条。
5. **业务观察**：仍无 C 级事件时，使用同一滚动48小时内、时间可精确核验的真实官方统计、公共项目/招采记录、权威研究、协会发布或成熟垂直/财经媒体的板块观察。它可放宽“建筑直接相关”和“重大突破”要求，但仍须真实标题、来源、直链与日期依据；卡片必须标记 `业务观察`，说明为什么与该板块有关。只有日期、没有时分的资料只能走第3层“48小时窗口观察”，不能借由观察类标签绕过时效要求。
6. **基线追踪卡**：仅当前五层均无法取得实时外部资料，或宿主没有实时检索能力时使用。输出 `基线追踪` 卡，包含：本次实时覆盖状态、已检查的权威来源家族、下一次要追踪的指标/主体、一个可访问的权威来源入口，以及“非当日新闻，不计入正式资讯”的醒目标识。

`基线追踪` 是连续服务信息，不是新闻，不得写成“暂无动态”，不得计入正式资讯、24/48 小时资讯、成功覆盖或来源多样性。`48小时窗口观察`、`扩展相关资讯`和`业务观察`都是可读的真实信息，但分别标记为 `observed`、`expanded`、`business-observation`，不得写入成功标记。正式资讯或48小时补充只要通过完整核验即可标记为 `complete`；两条或三条仅是候选筛选深度目标。若低于目标，必须保留扩展检索、候选排除依据和 `below_target_reason`，但不得以凑数为目的加入弱资讯。

## 低能力宿主

- 无 Python：可直接打开静态选择页、写 HTML、写 JSON；脚本校验改为“如可执行则运行”，并在审计中记录 `manual-validation`。不得因没有 Python 而放弃交互或输出。
- 无 webSearch 但可打开网址/RSS：从 `source-map.md` 的板块入口直接读最新列表、RSS、站内搜索或公开 JSON。
- 只能读取外部资料：使用通过 `news-input-schema.json` 的外部已验证输入；没有 Python 时按字段人工检查并注明。
- 没有任何实时网络或外部资料：只允许输出基线追踪卡与能力说明；不得编造今天的新闻，也不得写成功标记。

## 台账与 HTML 标记

- 台账状态新增 `observed`、`expanded`、`business-observation` 和 `baseline`；候选结论新增 `included-date-observation`、`included-expanded`、`included-business-observation`、`included-baseline`。
- `observed` 卡使用 `data-entry-kind="date-observation"`、`data-freshness-window="observed"`，并保留页面给出的日期和 `date-only` 时间依据。
- HTML 的基线卡使用 `.baseline-card`、`data-entry-kind="baseline"`，板块使用 `data-coverage-status="baseline"`。
- 只有基线卡的页面可以交付为“连续追踪版”，但不可以称为“完整实时日报”。
