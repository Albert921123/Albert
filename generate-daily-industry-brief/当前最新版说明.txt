  "distribution_version": "1.44.0"

本版重点：
0.0.0.1 防止“删完即判空”：任何板块在初筛、行业锚点或时窗筛选后低于目标，必须在初始候选逐条决定完成后再执行补救检索；补救检索同时新增来源族和主体类型，并将机器生成的 `post_filter_recovery` 原样写入台账。状态、台账或时序不一致时禁止渲染与交付。
0.0.0 建筑产业锚点与审计对账：数科、寻源、撮合、用工、海外、高管观点、企业经营、投融资的正式卡必须在原页明确出现建筑、建材、房地产、基础设施、工程服务/设备或项目供应链对象；拓展阅读覆盖五类深度入口。排除候选必须记录单一代码和具体原因，HTML 七列审计逐格与台账对账，计划时间、实际启动时间与延迟进入运行记录。
0.0 单一总控与证据链：正式实时版、补发版和定时版统一由 `run_pipeline.py` 从完整读取一直推进到正式交付；原始检索结果、板块画像、工作状态、台账、来源注册表、编辑模型、模板和 HTML 均以 SHA-256 绑定，任一环节缺失或改写都会阻断后续阶段。
0.0.1 原始检索回执与来源核验：每条查询必须保存真实结果数组、宿主工具名、带时区调用时间及调用标识；程序自行计算结果数并核对所有候选是否入账。候选的来源类别须通过 `source-registry.json` 与真实域名匹配，不能由 Agent 自行声称为官方来源。
0.0.2 结构化写作与确定性渲染：每张正式卡先写入带事实字段和四段分析的编辑模型；今日重点和今日推荐关注只能引用已核验24小时主窗口事件。HTML 由锁定模板和编辑模型确定性生成，不再允许临时脚本随意改变版式或遗漏内容。
0.1 四项反捷径硬闸门：每个板块必须分别保留四路查询证据；全板块台账和精确时窗未通过前状态机拒绝进入 HTML；`--allow-placeholders` 仅能校验原始模板；交付时由状态机重新执行台账、时窗、HTML、编辑质量和版式校验，不能用手填 passed 或半成品链接代替。
0. 新增可恢复运行计划：检索前先为全部板块建立字段、主体、官方记录、业务交集四条通道及候选审查深度；状态文件可逐板块记录检查点，中断后必须沿用同一计划恢复，禁止查几条就跳到 HTML。
1. 保留精确时分的24小时资讯和48小时补充；日期不完整的资料只能标为“48小时窗口观察”。
2. 对只有日期、但可确认处于整体48小时范围内的权威资料，输出“48小时窗口观察”，不再直接丢弃。
3. 严格实时资讯不足时，可使用真实且可点击的“扩展相关资讯”或“业务观察”填补板块；它们不计入严格实时完成，也不会写入成功标记。
4. 禁止匿名候选、虚构标题和没有真实直链的排除理由。
5. 无 web search 时可改用直接网址、RSS、公开 API 或外部结构化资讯文件；完全离线时只生成透明的基线追踪卡。
6. 实时生成不得直接复用旧日报或旧检索台账；高相关与高产出板块须并行执行一手/法定渠道与国家级、财经、垂直、招采或公告镜像等独立发现路径，减少国家级、企业级和项目级动态遗漏。
7. 新增反偷懒检索契约：每个板块必须记录检索路径、来源族、实际打开候选数、目标卡数及停止理由；高相关板块未达到两条时，必须完成额外发现路径并留存证据，否则校验失败。
8. 新增通用联网检索策略：只要任一公开网络路径可用（浏览器、HTTP、RSS、官网栏目、站内搜索、公开 API 或搜索页），必须执行实时检索；无 `webSearch`/`webFetch` 不得直接降级为“请用户提供 feed”。每个板块须记录实际传输路线、官网索引与独立发现路径；检索薄弱时先补检，再输出真实的扩展相关资讯或业务观察，尽量避免视觉空板块。
9. 新增严格交付闸门：预检只选择一个可用主路径，失效工具自动跳过；正式卡必须直达原记录、带时间精度和事件指纹。候选台账与 HTML 交叉校验，禁止旧闻填充、日期不明伪装实时、同一事件跨板块重复和审计数字不闭合。
10. 新增 Tavily 交互兜底：仅在宿主搜索、可控浏览器、公开网页/接口和已验证数据源均不可用时，自动说明原因、打开注册页、指导创建 Key、以遮蔽输入框粘贴并先测试；Key 不写入日报、HTML、台账、技能包或 GitHub。
11. 统一所有入口、说明、模板与校验规则：今日推荐关注只呈现并列来源事实，不显示箭头或因果链；移除管理层动作清单；交付校验会拒绝旧区块再次出现。
12. 新增定时与补发闭环：不得以 Active、任务名称或裸 RRULE 认定定时成功；必须同时核验调度时区证据和实际 nextRunAt。任何迟到唤醒、启动或恢复都会先判定同日补发，命中后在同一轮执行完整日报。
13. 将 Mode B 拆为 B1 个人云电脑自动化和 B2 普通浏览器/直连网页：yz claw 实际暴露 `yunzhu-browser-automation` 时必须先探测并记录状态，B1 可用即用于检索与原文核验，不能因缺少 webSearch 或未被用户提醒而跳过。
14. 将海外板块形成的深度检索方式推广为所有板块的统一硬约束：每板块必须绑定画像，并覆盖主体类型、来源类型和事件类型；低于目标时更换词组和来源族补检。代码核对工作状态、候选台账与 HTML，禁止在第一条结果后停止或用简化台账绕过正式交付门；当天确实只有一条合格资讯时仍只保留一条。
15. 补发改为“最新到期一期”：未到当天推送时间时补上一已排期日，已过推送时间时补当期；跨越多日也只补最新一期。成功标记按报告所属日期写入，避免凌晨补发被误记为当天而失去去重依据。
16. 新增两轮复筛闭环：单次空响应只能标记为路线失败；每个板块必须完成宽泛词、拆词、官方列表、原页打开以及更换关键词和来源族的第二轮发现。候选台账保留查询、链接、时间、原页状态和淘汰理由，禁止因少数板块失败清空已核验卡。
17. 新增精确48小时闸门：所有板块按生成时刻的上海时间精确比较24小时主窗口与24—48小时补充窗口；超窗、日期无法从原页核验或仅来自搜索摘要的候选只能留在内部台账，禁止进入资讯卡、今日重点和今日推荐关注。渲染前必须通过 `validate_time_window.py`。
