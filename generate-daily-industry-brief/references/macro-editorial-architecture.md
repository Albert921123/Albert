# 宏观—行业—企业/项目并列证据主题

日报不是项目公告清单，也不能把三条互不相关的新闻排成“宏观盘面”。每次生成应从已核验资讯中建立少量可追溯的**今日推荐关注**主题：并列展示政策或制度、行业或资本、企业或项目事实，帮助读者从不同层面理解同一经营议题。它们是并列证据，不表示因果、时间推进或必然传导关系。

## 强制编排

1. **今日推荐关注**：在正文、各板块卡之前，输出 2–3 个并列证据主题。每个主题保留三个横向卡位：`国家/政策或制度层`、`行业/资本或应用层`、`企业/项目层`；但卡位只用于组织不同层面的事实，不构成箭头、因果或时间顺序。每个节点必须链接到本期已渲染的独立资讯卡，且节点摘要须包含一个事实、数字或明确机制。
   - 只有存在同一经营议题下的独立事实时，才同时使用多个层面；两层事实可以形成主题，缺失层不补造、不写“待补”。
   - 若无当日国家级政策，只能如实使用已有的制度、市场、行业或项目事实，不得把地方项目、企业新闻或模型推断包装成国家趋势。
   - 三段卡后的补充说明只在确有必要时保留一段无字段标签的具体正文，说明应核验的经营节点，例如资金到位、招采、中标、接口、验收、订单、客户导入或运营现金流；不得冠以“核验重点”“管理动作”等标签，也不得写泛泛的“持续关注”。
   - 主题仅引用已分配的资讯卡，不能创建第二张同事件新闻卡，也不能改变一事一板块的归属。
2. **板块候选结构**：高产出或相关度 7–10 的板块，在有当前材料时必须比较：
   - 宏观/制度层：中央或地方政策、监管、统计、交易所、协会、行业供需或资本信息；
   - 行业/公司层：龙头企业、上市披露、行业研究、产业链、产品或产能信息；
   - 项目/交易层：招标、中标、融资、开工、投产、合作、并网、采购、运营节点。
   三层是候选池比较结构，不是要求虚构三条新闻，也不是要求把它们写成一条因果链。只要后续候选通过时效、来源、相关性和去重核验，就必须渲染。
3. **多卡顺序**：同一板块有多条时，优先安排“宏观或行业判断卡”在前，再安排企业/项目卡；不得连续堆叠多个弱相关招标标题而没有解释其共同的行业方向。
4. **低产出例外**：若当前窗口没有宏观或行业层的合格内容，可保留项目卡，但审计须说明已检查的宏观/行业来源与具体排除原因。不得用旧闻填充。
5. **不重复**：同一事件只归最相关的一个板块。今日推荐关注只能以锚点引用该卡，不能重复渲染为其他板块的独立新闻卡。

## 页面呈现

使用模板的浅色 `management-map` 区域，不使用深色、无来源链接的“宏观盘面”。每个主题有三个横向并列证据卡；桌面端三列排列、移动端按普通阅读顺序纵向排列，不显示箭头。左侧导航只提供“今日推荐关注”入口。

不得额外渲染“管理层动作清单”或以其替代今日推荐关注。页面中的推荐主题、正文和检索审计均不得写入检索过程、校验状态、时间戳精度或“覆盖不足”等生产元数据。

## 板块映射示例

| 板块 | 宏观/行业优先来源 | 项目/交易优先来源 |
|---|---|---|
| 政府宏观、城市更新、专项债 | 国务院、部委、省市政府、财政/发改、交易所 | 更新单元、贷款、专项债、公共资源项目 |
| 行业数据、房地产、REITs | 统计局、交易所、监管、协会 | 企业披露、资产包、发行/询价、项目招采 |
| AI、建筑软件、数据中心、光学光电子 | 工信/网信、行业协会、龙头公司、研究机构 | 产品采购、机房/算力、产线、客户部署 |
| 绿色低碳、光伏、海运 | 能源/生态主管部门、港航/能源统计、行业协会 | 并网、储能、光储充、船舶、港口、工程采购 |

## 质量判定

将“只有一条项目卡”视为未完成候选比较，而不是正常成品。只有额外发现路径已完成、第二张卡被逐条排除且审计具备具体证据时，才允许单卡交付。`max_items_per_topic` 是上限；没有“输出到两条或三条便停止”的规则。
