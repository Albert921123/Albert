# 宏观—行业—企业/项目证据链

日报不是项目公告清单，也不能把三条互不相关的新闻排成“宏观盘面”。每次生成应从已核验资讯中建立少量可追溯的**今日经营主线**：说明政策或制度、行业或资本机制，如何连接到企业或项目事实，并给出下一项管理动作。

## 强制编排

1. **今日经营主线**：在正文、各板块卡之前，输出 2–3 条证据链。每条采用固定顺序：`国家/政策或制度层 → 行业/资本或应用层 → 企业/项目层 → 管理动作`。每个节点必须链接到本期已渲染的独立资讯卡，且节点摘要须包含一个事实、数字或明确机制。
   - 只有三层证据确实存在相同的传导关系时，才标记为“政策—行业—项目三层已具备”。
   - 只有两层证据时，明确写为“两层待补”；若无当日国家级政策，只能写“制度/市场层”，不得把地方项目、企业新闻或模型推断包装成国家趋势。
   - 管理动作必须说明下一步应核验的经营节点，例如资金到位、招采、中标、接口、验收、订单、客户导入或运营现金流；禁止写“持续关注”。
   - 证据链使用的是跨板块解释，不能创建第二张同事件新闻卡，也不能改变一事一板块的归属。
2. **板块候选结构**：高产出或相关度 7–10 的板块，在有当前材料时必须比较：
   - 宏观/制度层：中央或地方政策、监管、统计、交易所、协会、行业供需或资本信息；
   - 行业/公司层：龙头企业、上市披露、行业研究、产业链、产品或产能信息；
   - 项目/交易层：招标、中标、融资、开工、投产、合作、并网、采购、运营节点。
   三层是候选池结构，不是要求虚构三条新闻。只要后续候选通过时效、来源、相关性和去重核验，就必须渲染。
3. **多卡顺序**：同一板块有多条时，优先安排“宏观或行业判断卡”在前，再安排企业/项目卡；不得连续堆叠多个弱相关招标标题而没有解释其共同的行业方向。
4. **低产出例外**：若当前窗口没有宏观或行业层的合格内容，可保留项目卡，但审计须说明已检查的宏观/行业来源与具体排除原因。不得用旧闻填充。
5. **不重复**：同一事件只归最相关的一个板块。经营主线只能以锚点引用该卡，不能重复渲染为其他板块的独立新闻卡。

## 页面呈现

使用模板的浅色 `management-map` 区域，不使用深色、无来源链接的“宏观盘面”。每条主线应有三个横向层级卡和一个完整的行动段；桌面端三列排列、移动端按箭头顺序纵向排列。左侧导航应提供“经营主线”与“管理动作”入口。

`管理层动作清单` 替代泛泛的“今日信号”：输出 2–3 条跨板块结论，每条必须点名已验证事实或数字、机会/风险、以及下一项观察或动作。不得写入检索过程、校验状态、时间戳精度或“覆盖不足”等生产元数据。

## 板块映射示例

| 板块 | 宏观/行业优先来源 | 项目/交易优先来源 |
|---|---|---|
| 政府宏观、城市更新、专项债 | 国务院、部委、省市政府、财政/发改、交易所 | 更新单元、贷款、专项债、公共资源项目 |
| 行业数据、房地产、REITs | 统计局、交易所、监管、协会 | 企业披露、资产包、发行/询价、项目招采 |
| AI、建筑软件、数据中心、光学光电子 | 工信/网信、行业协会、龙头公司、研究机构 | 产品采购、机房/算力、产线、客户部署 |
| 绿色低碳、光伏、海运 | 能源/生态主管部门、港航/能源统计、行业协会 | 并网、储能、光储充、船舶、港口、工程采购 |

## 质量判定

将“只有一条项目卡”视为未完成候选比较，而不是正常成品。只有额外发现路径已完成、第二张卡被逐条排除且审计具备具体证据时，才允许单卡交付。`max_items_per_topic` 是上限；没有“输出到两条或三条便停止”的规则。
